# Repository Guide

## Where to work

- Go 1.27.1 module (`go.mod`): `main.go` handles commands, flags and the Gio window; `internal/install` owns offline per-user installation; `packaging/assets.go` embeds artwork/templates/wrappers; `internal/app` owns the Polochon client, catalog, navigation, UI, subtitles, refresh, and mpv; `internal/driver` and `cmd/gio-control` provide headless UI testing.
- This is a TV/remote/Steam Deck interface. Preserve directional-key/controller navigation and fullscreen playback; mouse behavior is secondary. The radix tree is the core title-search interaction.
- Keep changes with their owner in `internal/app`: `core.go` (API/config), `listing.go` (catalog builders), `input.go`/`browse_navigation.go` (actions/navigation), `player.go` (mpv/IPC/resume), `refresh.go` (async refresh), `subtitles.go` (popup), `format.go` (display formatting).
- For build, configuration, flags, Linux desktop registration, and optional Steam Deck setup, consult `README.md` and `packaging/linux/README.md` when relevant rather than assuming host services are available.

## Behavioral invariants (when touching the relevant code)

- `actionForKey` maps keys to actions; preserve arrow/vim aliases and dispatch priority: subtitle popup > detail > browse. In browse, Right opens a selected terminal's detail; Enter does **not** open browse terminals. On the mode rail, Up/Down switches the listing without losing the browse section; Right returns to content.
- Preserve show detail focus: start on season tabs, Down/Enter enters episodes, Enter on an episode plays it. Left backs out of detail (from show tabs, first move to the first tab). Play is pointer-accessible but not another D-pad focus zone.
- `MediaItem.Type` uses `MediaKind` (`mediaKindMovie`, `mediaKindShow`), not raw type strings. Use `movieMediaKey`/`episodeMediaKey` for playback and resume. Listing-built terminal `RadixNode.Media` carries identity; string-only `NewRadixTree` callers intentionally have nil media.
- In `listing.go`, keep builders package-private, build movie/show sections separately, merge movie mappings first, and never mutate shared listing items. Preserve IMDb-ID input order in `MovieCollection.List`/`ShowCollection.List`: it determines duplicate title-map winners.
- `APIClient.snapshotFor` shallow-copies cached slices under `RLock` and runs builders after unlocking; custom snapshots must not replace default client state. It returns `LibrarySnapshot` without error. `App.browse.library` holds snapshot + mode; replace its snapshot only through `applyLibrarySnapshot` and access roots via `sectionRoot`.
- A `refreshResult` snapshot is valid only if `err == nil`. On failure keep displayed catalog, navigation, detail and caches; clear refreshing, log the error, and retain the compact header failure state until retry/success.
- Movie and episode launch paths share `buildPlayerCommand`. External subtitle URL failures are non-fatal; video URL failure prevents launch. `asyncCache` resolves fetch failures to zero values (no retry); `drain` is side-effect-only and `onDone` invalidates the UI on success or failure.
- In `DateAdded` test fixtures, set nested `papi.Movie.Movie.BaseVideo.VideoMetadata` and `papi.Episode.ShowEpisode.BaseVideo.VideoMetadata` dates; show date uses the newest non-zero nested episode date. A single-item `NewRadixTree` can log an existing root-level compression warning; check the tests rather than treating the warning alone as a regression.

## Detail UI (when changing detail pages)

- Design for 10-foot viewing: low density, obvious Play action, clear focus, compact 24dp outer spacing (scaled with the UI), without reserving a fixed 5% overscan border. Keep the existing help-bar hints and ordering. Do not change browse-preview scrims while changing full-screen movie/show details.
- Never put important text directly on uncontrolled fanart/posters: use a dark surface/gradient/scrim. Check final composited contrast (WCAG AA: 4.5:1 normal, 3:1 large); `colorMuted` is only for disabled or nonessential hints. Inspect both bright and dark artwork.
- Use embedded proportional Roboto (`text.NoSystemFonts()`) for all text, including technical values and keycaps; retain normal/medium/bold/italic and Noto Sans Symbols/Symbols 2 glyph fallbacks. Keep the pinned, SHA-verified font workflow in `build.sh`.
- Constrain/clamp descriptions to roughly 55–70 characters/line with ~1.35–1.5 line spacing. On shows, prioritize the selected episode synopsis over repeated show copy. Order episode content: title/Play, air date/runtime, synopsis, then one subdued technical line (size, quality, codecs, container, release group); do not restore bright file badges.
- For detail-page changes, inspect headless screenshots at 1080p and a smaller viewport with bright and dark fanart. References: [Android TV typography](https://developer.android.com/design/ui/tv/guides/styles/typography), [Android TV scrims](https://developer.android.com/design/ui/tv/guides/components/featured-carousel), [Fire TV UX](https://developer.amazon.com/docs/fire-tv/design-and-user-experience-guidelines.html), [WCAG contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum).

## Known platform limitations

- Steam Deck Gaming Mode sleep inhibition is not solved by the generic `packaging/linux/mpv-inhibit.sh` wrapper. On SteamOS 3.8.28 stable, a confirmed idle/block lock did not prevent suspend; a sleep/block lock kept SSH usable but left the display black, unrecoverable by pointer activity. See [tested behavior and upstream issues](packaging/linux/README.md#automatic-sleep-during-playback). Do not recommend a stronger lock as a verified fix or add synthetic input/global power-setting changes unless explicitly requested. Preserve manual suspend requirements and verify behavior on the target SteamOS/client versions.
- The user-requested, opt-in `packaging/linux/mpv-keepawake.sh` workaround uses host xdotool with unused raw keycode 97 for the entire launcher lifetime (including pause/background playback). Keep it separate from the inhibitor wrapper and from pépé's Go/Lua code. A manual pulse test worked on the Deck; do not conflate that with full wrapper validation or proper inhibition support. The user validates this wrapper on-device; keep only the static `shellcheck packaging/linux/mpv-keepawake.sh` check.

## Checks and headless UI

- For desktop packaging changes, run `shellcheck scripts/install-desktop.sh scripts/test-desktop.sh` and `scripts/test-desktop.sh`; these use isolated HOME/XDG fixtures and mocked downloads. For standalone installation changes, also run `shellcheck build.sh scripts/fetch-assets.sh scripts/test-assets.sh scripts/test-install.sh packaging/linux/mpv-auto.sh`, `scripts/test-assets.sh`, `scripts/test-install.sh`, and `go test ./internal/install ./packaging`. Artwork is downloaded and SHA-verified from `packaging/assets.txt` into gitignored `packaging/embed` at build time, never committed or fetched by installation/launch. Keep the shared manifest usable by future macOS packaging; keep source registration separate from installed-copy ownership.
- Run focused tests for the changed area, then `go test ./...` for code changes. Run `go test -race ./...` after async refresh/cache/subtitle/player/UI changes; `golangci-lint run` for cleanup. Tests are local and require no Polochon service.
- Use `gofmt -w <changed-go-files>`; build with `go build .` when relevant.
- Embedded fonts and artwork are gitignored: on a fresh clone, `./build.sh` fetches and SHA-verifies them before `go build .` can succeed. Do not assume a sibling Polochon checkout; the upstream module is pinned in `go.mod`.
- For Linux headless tests/driver, set `EGL_PLATFORM=surfaceless` and `LIBGL_ALWAYS_SOFTWARE=1`. Run `go test ./internal/driver` for driver changes. In Pi use `gio_start`, `gio_tree`, `gio_key`, `gio_resize`, `gio_screenshot` (and `gio_restart` after UI edits); prefer semantic targets if testing pointer controls. The driver uses an empty offline catalog without config; real catalog needs `GIO_CONTROL_CONFIG` or `POLOCHON_URL`/`POLOCHON_TOKEN`.
- With a populated catalog, from home: Left (mode rail), Up (Last added), Right (content), Right (Movies), then Right through any radix prefixes and on a terminal to open detail. Enter on detail activates Play, so do not use it to navigate there. Use `gio_tree` to confirm the state instead of assuming a fixed number of key presses.
