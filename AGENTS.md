# Repository Guide

## Where to work

- Go module (`go.mod`): the `go` line is the minimum and must not exceed the Go in the current NixOS stable release (downstream Nix builds use `GOTOOLCHAIN=local`); `toolchain go1.27.4` selects the CI/release and default developer toolchain. `main.go` handles commands, flags and the Gio window; `internal/install` owns offline per-user installation; `packaging/assets.go` embeds artwork/templates/wrappers; `internal/app` owns the Polochon client, catalog, navigation, UI, subtitles, refresh, and mpv; `internal/driver` and `cmd/gio-control` provide headless UI testing.
- `gioui.org` is replaced in `go.mod` by the fork `github.com/gregdel/gio` (branch `gregdel`: upstream main plus two renderer fixes meant for upstream: a panic when a full-screen opaque fill follows an opacity layer, and scaled images drawn through clip paths, ~11 ms per full-screen layer on the Pi's GPU). Move it with `go mod edit -replace=gioui.org=github.com/gregdel/gio@COMMIT` and `go mod tidy`, then update `vendorHash` in `packaging/nix/package.nix`; drop the `replace` once a Gio release contains both fixes.
- This is a TV/remote/Steam Deck interface. Preserve directional-key/controller navigation and fullscreen playback; mouse behavior is secondary. The radix tree is the core title-search interaction.
- Deployments: keyboard users run Linux (US and French AZERTY layouts) and macOS (French); Gio reports the letter the layout produces, so letter shortcuts work on both. HDMI-CEC is used only by the pepeOS Raspberry Pi appliance (`../pepeOS`), which sets no keyboard layout (US default). It installs `packaging/linux/cec.toml` and loads it with `ir-keytable` from udev, and `packages/pepe.nix` there greps its mappings, so update both when changing CEC keys. `cec.toml` letter keycodes are physical positions, valid only under that US layout.
- Keep changes with their owner in `internal/app`: `core.go` (API/config), `listing.go` (catalog builders), `input.go`/`browse_navigation.go` (actions/navigation), `player.go` (mpv/IPC/resume), `refresh.go` (async refresh), `subtitles.go` (popup), `format.go` (display formatting).
- For build, configuration, flags, Linux desktop registration, and optional Steam Deck setup, consult `README.md` and `packaging/linux/README.md` when relevant rather than assuming host services are available.

## Behavioral invariants (when touching the relevant code)

- `actionForKey` maps keys to actions; preserve arrow/vim aliases and dispatch priority: setup screen > subtitle popup > detail > browse. The setup screen (`setup.go`) replaces the UI when the config is missing, invalid or still has the template token; `main.go` writes the template first when no config exists. The setup screen and the Settings rail page share `settings.go`; a valid save writes the file and `Run`/`RunSetup` return `ErrRestart`, so `main.go` re-execs. In browse, Right or Enter opens a selected terminal's detail. On the mode rail, Up/Down switches the listing without losing the browse section; Right returns to content.
- Preserve show detail focus: start on season tabs, Down/Enter enters episodes, Enter on an episode plays it. Left backs out of detail (from show tabs, first move to the first tab). Show detail has no Play button: clicking a season tab selects it, clicking an episode row selects and plays it, like a click on a browse row. Subtitles have no button; `s` opens the popup.
- `MediaItem.Type` uses `MediaKind` (`mediaKindMovie`, `mediaKindShow`), not raw type strings. Use `movieMediaKey`/`episodeMediaKey` for playback and resume. Listing-built terminal `RadixNode.Media` carries identity; string-only `NewRadixTree` callers intentionally have nil media.
- In `listing.go`, keep builders package-private, build movie/show sections separately, merge movie mappings first, and never mutate shared listing items. Preserve IMDb-ID input order in `MovieCollection.List`/`ShowCollection.List`: it determines duplicate title-map winners.
- `APIClient.snapshotFor` shallow-copies cached slices under `RLock` and runs builders after unlocking; custom snapshots must not replace default client state. It returns `LibrarySnapshot` without error. `App.browse.library` holds snapshot + mode; replace its snapshot only through `applyLibrarySnapshot` and access roots via `sectionRoot`.
- A `refreshResult` snapshot is valid only if `err == nil`. On failure keep displayed catalog, navigation, detail and caches; clear refreshing, log the error, and retain the compact header failure state until retry/success. A failed first load (`Run`'s `loadErr`) starts empty and retries with capped backoff until it succeeds, because SSE reconnects send no event.
- The settings form edits file values (`ReadConfigFile`), never env/flag overrides, and `SaveConfigFile` updates only the form values that differ from the file in the YAML AST so comments and other keys survive. A save must never leave a TV-only user stuck after the restart: `SaveConfigFile` refuses output that does not read back as the form's values, and a web remote that cannot listen is logged and shown on its page instead of stopping `Run`. Gio gives a key to any matching key filter instead of inserting its text into the focused editor, so key bindings are scoped to the focused `keyTag`, and while a field is edited only `editKeys`, scoped to the editor, are read.
- The catalog draws the selected title's fanart full-bleed behind the list (`backdrop.go`). The header, rail and list must stay left of `catalogListEdge` (shared with `layoutCatalog` via `catalogLeftWidth`), where the veil is opaque over an ambient copy clamped to `ambientMaxLuminance` (`TestCatalogBackdropRenderedContrast`); the terminal preview keeps its `scrim`, drawn window-wide by `layoutCatalog` from `previewTextTop`. Only terminal previews set it, so sharp fanart is shown only while a terminal is selected; other previews switch to the ambient copy at once (`TestBackdropNeverSharpWithoutScrim`). `backdropState` holds the shown artwork, so cache resets on refresh do not blank it (`TestBackdropSurvivesRefresh`). Fanart is cached in `App.backdrops`, shared with detail pages; posters stay in `App.images`.
- `LogBuffer` (`logbuffer.go`) keeps Info+ entries for the TV Logs page and the unauthenticated web `/logs`. It redacts at write time (Polochon token, URL credentials and queries, auth header values), and the log file gets the same redacted records; still never log secrets. mpv output is read from a separate `os.Pipe`, so `cmd.Wait` does not wait for wrapper children that inherit it.
- While mpv runs, web remote navigation goes to mpv (`handleRemoteAction`: `pepe.lua`'s `remote` script message, or fixed commands without the script), never to the hidden Gio UI.
- Watch progress (`progress.go`) targets SD cards: only `Run` opens the file (`save_progress`), so `New`, tests and the driver stay in memory and never touch the user's state. Writes are coalesced by one writer goroutine and flushed by `Close`; never write on navigation or periodically during playback; each queued episode is recorded when mpv ends it (`end-file`), so a crash keeps a binge's progress. Stopping at ≥90% of mpv's `duration` counts as watched, because users quit at the credits and rarely reach EOF.
- An episode launch queues the whole show in mpv's playlist over IPC (`loadfile` `insert-at`/`append` with its `index` parameter, mpv 0.38+, within the README's 0.41+ minimum), never on the command line: pepeOS's launcher passes exactly one media URL after `--`, and command-line options apply to every entry, so each queued entry sets its own `start`, `title`, `force-media-title` and `sub-files` (an empty value clears the launched file's subtitles). The tracker maps mpv's `playlist_entry_id` to media keys; `TestMPVInterfaceIntegrationPlaylist` checks this against real mpv.
- Movie and episode launch paths share `buildPlayerCommand`. External subtitle URL failures are non-fatal; video URL failure prevents launch. `asyncCache` resolves fetch failures to zero values; only errors `retryable` reports as transient (artwork: network/timeout, 5xx/408/429, interrupted body via `transientError`) are refetched after a capped backoff, with artwork widgets scheduling the redraw. `drain` is side-effect-only and `onDone` invalidates the UI on success or failure.
- In `DateAdded` test fixtures, set nested `papi.Movie.Movie.BaseVideo.VideoMetadata` and `papi.Episode.ShowEpisode.BaseVideo.VideoMetadata` dates; show date uses the newest non-zero nested episode date. A single-item `NewRadixTree` can log an existing root-level compression warning; check the tests rather than treating the warning alone as a regression.

## Detail UI (when changing detail pages)

- Design for 10-foot viewing: low density, obvious play action (the movie Play button; on shows, the focused episode row), clear focus, compact 24dp outer spacing (scaled with the UI), without reserving a fixed 5% overscan border. Keep the existing help-bar hints and ordering. Do not change browse-preview scrims while changing full-screen movie/show details.
- Never put important text directly on uncontrolled fanart/posters: use a dark surface/gradient/scrim. Check final composited contrast (WCAG AA: 4.5:1 normal, 3:1 large); `colorMuted` is only for disabled or nonessential hints. Inspect both bright and dark artwork.
- Use the least darkness that keeps detail text at AA, so fanart stays visible; don't darken fanart where no text sits. In linear-light blending `colorDetailPanel`'s `0xfa` is already that minimum over white (`TestDetailPanelIsMinimal`).
- Use embedded proportional Roboto (`text.NoSystemFonts()`) for all text, including technical values and keycaps; retain normal/medium/bold/italic. It is the only font and has no fallback, so Gio text must stay within Roboto's glyphs: arrows and play are Material icons (`keycapArrows`, `playIcon`). Keep fonts pinned and SHA-verified in `packaging/fonts.txt` (fetched by `build.sh`).
- Constrain/clamp descriptions to roughly 55–70 characters/line with ~1.35–1.5 line spacing. On shows, prioritize the selected episode synopsis over repeated show copy. Order episode content: title, resume position (own line, since Enter resumes), air date/runtime, synopsis, then one subdued technical line (size, quality, codecs, container, release group); do not restore bright file badges.
- For detail-page changes, inspect headless screenshots at 1080p and a smaller viewport with bright and dark fanart. References: [Android TV typography](https://developer.android.com/design/ui/tv/guides/styles/typography), [Android TV scrims](https://developer.android.com/design/ui/tv/guides/components/featured-carousel), [Android TV color and gradient banding](https://developer.android.com/design/ui/tv/guides/foundations/color-on-tv), [Fire TV UX](https://developer.amazon.com/docs/fire-tv/design-and-user-experience-guidelines.html), [WCAG contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum), [WCAG G18: text contrast over images](https://www.w3.org/WAI/WCAG22/Techniques/general/G18).

## Design and motion (when changing how the UI looks or moves)

- `DESIGN.md` is the design reference: colour roles, type and spacing scales, the focus model and motion. Follow it for any visual change. If a change needs a new rule, update `DESIGN.md` in the same change rather than diverging.
- **Focusable lists:** every focusable list goes through `focusList` (or `focusListRow` for a non-scrolling `Flex`, like the rail), with `focusRowShell` rows. Never paint a focus fill or ring inside a row. Give each list its own `listMotion` and a key that changes with its contents, so new contents snap.
- **Motion mechanics:**
  - Compute motion from `frameTime(gtx)`, and request frames only through `a.animating`, which feeds `Loading`. Driver screenshots therefore wait for motion; `--no-wait` captures mid-motion.
  - Never let motion delay or queue input.
- **Tests:**
  - Headless fixtures lay out through `settledLayout`, whose clock moves a second per frame, and `headlessKey` settles after each key. Assertions therefore see settled positions.
  - Motion itself is tested frame by frame with explicit `gtx.Now` (`motion_test.go`, `detail_fade_test.go`).

## Known platform limitations

- Steam Deck Gaming Mode sleep inhibition is not solved by the generic `packaging/linux/mpv-inhibit.sh` wrapper. On SteamOS 3.8.28 stable, a confirmed idle/block lock did not prevent suspend; a sleep/block lock kept SSH usable but left the display black, unrecoverable by pointer activity. See [tested behavior and upstream issues](packaging/linux/README.md#automatic-sleep-during-playback). Do not recommend a stronger lock as a verified fix or add synthetic input/global power-setting changes unless explicitly requested. Preserve manual suspend requirements and verify behavior on the target SteamOS/client versions.
- The user-requested, opt-in `packaging/linux/mpv-keepawake.sh` workaround uses host xdotool with unused raw keycode 97 for the entire launcher lifetime (including pause/background playback). Keep it separate from the inhibitor wrapper and from pépé's Go/Lua code. A manual pulse test worked on the Deck; do not conflate that with full wrapper validation or proper inhibition support. The user validates this wrapper on-device; keep only the static `shellcheck packaging/linux/mpv-keepawake.sh` check.

## Checks and headless UI

- For desktop packaging or standalone installation changes, run `shellcheck build.sh scripts/*.sh packaging/linux/*.sh` (CI pins the shellcheck release in `ci.yml` to the version developers run; bump its URL and SHA-256 together), `scripts/test-assets.sh`, `scripts/test-install.sh`, and `go test ./internal/install ./packaging`. These use isolated HOME/XDG fixtures and mocked downloads. Artwork is downloaded and SHA-verified from `packaging/assets.txt` into gitignored `packaging/embed` at build time, never committed or fetched by installation/launch. Keep the shared manifest usable by future macOS packaging; do not overwrite legacy checkout registrations or unrelated desktop entries.
- Artwork is hosted as assets of `assets-vN` GitHub releases on `gregdel/pepe`. To change artwork, never re-upload into an existing tag: create the next `assets-vN` with `gh release create --draft --latest=false`, compare the uploaded asset digests to the local SHA-256s, publish with `gh release edit --draft=false --latest=false`, and update `packaging/assets.txt` hashes and URLs in one commit.
- Every push to master publishes a GitHub release tagged with the commit time in UTC (`YYYYMMDD-HHMMSS`, the same as the Nix flake version) from the `release` job in `.github/workflows/ci.yml`, after all test and package jobs pass; its notes start with `packaging/release-notes.md` (`@VERSION@` is replaced by the tag) before the generated changelog. Linux tarballs (`scripts/package-linux.sh`) are built on `ubuntu-22.04`/`ubuntu-22.04-arm` as the oldest supported library baseline; `scripts/check-linux-binary.sh` enforces the allowed linked libraries and maximum glibc symbol, so update its allowlist deliberately when Gio or Go changes what is linked. macOS DMGs (`scripts/package-macos.sh`, smoke-tested by `scripts/test-package-macos.sh`) are built natively on `macos-15` and `macos-15-intel` for macOS 13+ (Go 1.27's minimum, also passed to cgo via `MACOSX_DEPLOYMENT_TARGET`); they are ad-hoc signed, not notarized.
- The Nix package (`packaging/nix/package.nix`, exposed by `flake.nix`) fetches fonts/artwork from the same manifests and skips tests (no GPU in the sandbox). It is a cheap wrapper (GL/Vulkan loader, optional mpv on PATH) around the Go build in `passthru.unwrapped`; keep runtime paths out of the Go build, because pepeOS compiles it under AArch64 emulation and calls it with `mpv = null`, `withX11 = false`, `withVulkan = false`, using `share/pepe` (CEC keymap, mpv CEC bindings, OSD script, fonts). When `go.sum` changes, update `vendorHash` (set `lib.fakeHash`, build, copy the reported hash). Flakes only see git-tracked files; to build uncommitted changes without copying the large untracked `.pi` directory, use `nix build --impure --expr '(builtins.getFlake "nixpkgs").legacyPackages.x86_64-linux.callPackage ./packaging/nix/package.nix {}'`.
- Run focused tests for the changed area, then `go test ./...` for code changes. Run `go test -race ./...` after async refresh/cache/subtitle/player/UI changes; `golangci-lint run` for cleanup. Tests are local and require no Polochon service.
- Use `gofmt -w <changed-go-files>`; build with `go build .` when relevant.
- Artwork/animation performance: measure with the opt-in `PEPE_PERF=1 go test ./internal/app -run 'TestPerfScenario$' -v` (400 titles over a simulated link, `PEPE_PERF_LATENCY_MS`/`PEPE_PERF_MBPS`; its artwork mix and default link match a real server, sampled with `PEPE_PERF_REAL=1 … -run TestPerfRealArtwork` using `POLOCHON_URL`/`POLOCHON_TOKEN`) and the `BenchmarkArtwork*` benchmarks. Its frame times come from llvmpipe and a shared CPU, so compare them only on a quiet machine; artwork-visibility and network numbers are stable. Gio frees any texture not drawn in the previous frame, so re-showing cached artwork re-uploads it.
- After `internal/app/mpv/pepe.lua` changes, run `luajit tests/mpv-osd.lua internal/app/mpv/pepe.lua` (offline, mocked `mp`; CI runs it) and the opt-in real-mpv `PEPE_TEST_MPV=1 go test ./internal/app -run TestMPVInterfaceIntegration -count=1`. Targets include mpv 0.41, which lacks `user-data/mpv/context-menu/open`.
- Embedded fonts and artwork are gitignored: on a fresh clone, `./build.sh` fetches and SHA-verifies them before `go build .` can succeed. Do not assume a sibling Polochon checkout; the upstream module is pinned in `go.mod`.
- For Linux headless tests/driver, set `EGL_PLATFORM=surfaceless` and `LIBGL_ALWAYS_SOFTWARE=1`. Run `go test ./internal/driver` for driver changes. In Pi use `gio_start`, `gio_tree`, `gio_key`, `gio_resize`, `gio_screenshot` (and `gio_restart` after UI edits). Other harnesses use `scripts/gio` (sets the EGL variables; state, log and screenshots in gitignored `tmp/gio`): `scripts/gio start [--mock]`, then `tree --compact [--selected|--all]`, `key NAME`, `click LABEL|--id N|--xy X Y` (key/click print the focused node, so a tree is rarely needed after each step), `resize W H`, `screenshot [--crop X Y W H] [--scale F]` (prints the PNG path to read; first waits up to 8s for library/artwork loading and notes on stderr if it was still loading; `--no-wait` skips), `wait [SECONDS]`, `log`, `stop`, and `restart` after UI edits; `scripts/gio help` lists all. D-pad focus is the semantic `[selected]` node (`markSelected` in `internal/app/widgets.go`); keep it on new focusable rows. Prefer semantic targets if testing pointer controls. Pointer actions run before the next frame's layout, so after `driver.Click` call `driver.Settle()` (`headlessClick` in tests; `gio-control` already settles). The driver uses an empty offline catalog without config; real catalog needs `GIO_CONTROL_CONFIG` or `POLOCHON_URL`/`POLOCHON_TOKEN` (and, in a sandbox, a CA bundle at `/etc/ssl/certs/ca-certificates.crt`). `--mock`/`mockMpv` uses an offline catalog and a stub mpv; without it, Play launches real mpv. The mock catalog (`headless_fixture.go`) serves generated artwork through `artworkClient` (`headless_artwork.go`), so it takes the real download/decode/cache path; add a title there, with its case in the plot, for a new artwork scenario.
- With a populated catalog, from home: Left (mode rail), Down (Last added; Up from Smart list wraps to Settings, then Logs, then Web remote), Right (content), Right (Movies), then Right through any radix prefixes and on a terminal to open detail. Enter on detail activates Play, so do not use it to navigate there. Use `gio_tree` or `scripts/gio tree --compact` to confirm the state instead of assuming a fixed number of key presses.
